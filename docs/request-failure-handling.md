# 请求故障分类与处理

本项目将请求失败按认证、基础设施、接口契约和业务结果处理。会话探活告警只记录阶段、失败原因、HTTP 状态和脱敏错误类型；不得输出 Cookie、Token、账号密码、Webhook、完整请求体或内部 URL。

## 认证失效

| 现象 | 探活原因或下载标记 | 当前动作 | 持续出现时检查 |
| --- | --- | --- | --- |
| HTTP 302 | `status_not_allowed`，或 `Location` 指向登录页 | 视为认证失效；进入全局登录锁，锁内复检后仅执行一次完整刷新 | SSO 会话是否过期、Cookie 域和阶段配置 |
| HTTP 401、403 | `session_expired` 或下载错误中的 `HTTP 401/403` | 同上 | 登录是否成功写入目标阶段的 Cookie/Storage |
| HTTP 200 但返回登录页或过期语义 | `session_expired`；包括登录页关键字、`reCode=1101/401/403`、登录或超时消息 | 同上；HTTP 200 不代表会话有效 | 探活的 JSON 成功条件和上游接口返回 |
| Cookie 阶段缺失、认证材料缺失 | `missing_stage`、`missing_authentication_material` | 视为认证问题并尝试一次刷新 | `required_stages`、`headers_from_cookies`、`headers_from_session_storage` 配置 |
| JSON 成功值不匹配 | `json_value_mismatch` | 先按认证问题刷新一次 | 若刷新后仍失败，按接口契约变更处理，不要连续重登 |

`302` 是当前会话探活的认证状态码。其他 3xx 只有响应位置明确指向登录页时才认定为认证失效；非登录重定向应先检查接口地址、网关和反向代理规则。

业务 Flow 对上述认证失效只有一次刷新预算，并仅重试失败的业务请求一次。Session Keeper 每 10 分钟执行一次，单次 Run 最多执行一次完整登录；失败时记录并抛出异常，由下一轮调度再次检查。Keeper 不发送失败或恢复通知。登录锁始终保留，防止并发覆盖共享 Cookie。

## 基础设施问题

| 现象 | 探活原因或状态 | 当前动作 | 排查方向 |
| --- | --- | --- | --- |
| 连接超时、DNS、TLS、代理或请求库异常 | `probe_error`，日志可带脱敏 `错误类型` | 抛出基础设施故障，不触发浏览器重登 | 网络、DNS、证书、代理和服务可用性 |
| HTTP 429 | `status_not_allowed` | 视为基础设施或限流问题，不重登 | 降低并发、确认限流窗口与重试策略 |
| HTTP 5xx | `status_not_allowed` | 视为上游或网关问题，不重登 | 上游服务、网关、维护窗口和请求负载 |
| 非登录重定向、非预期空响应、需要 JSON 但不是 JSON | `status_not_allowed`、`empty_body`、`json_required` | 当前请求失败，不重登 | 接口地址、响应协议、探活配置和上游变更 |

Session Keeper 会将基础设施故障作为本次 Run 失败抛出，不在同一轮 Prefect Run 中等待 60 秒重做整套登录，也不发送会话通知。

## 下载与外部服务

| 请求类型 | 可自动恢复情形 | 不应使用登录恢复的情形 |
| --- | --- | --- |
| 业务报表下载 | 错误已明确表明认证失效：`session expired`、`HTTP 401/403`、`reCode=1101`、登录页或登录超时标记；或者 `302` 的跳转位置明确指向登录页时，刷新一次会话后重试该下载。`returncode=1` 且消息为“下载文件错误”时，按 `transient_business_retries` 以固定 2 秒间隔有限重试，不刷新会话 | 非登录重定向、HTTP 4xx/5xx、响应格式错误、业务数据为空，以及其他业务错误 |
| 腾讯文档 API | 网络异常，以及 429、500、502、503、504 会按配置指数退避；默认最多 3 次 | 其他 HTTP 错误、API `ret/code` 业务错误、无效 Sheet 范围或权限配置错误 |

下载响应中的 URL、重定向位置和正文预览仅可保留在本地受控诊断，不应复制到 Prefect 告警或企业微信消息。

## 企业微信告警

Session Keeper 只负责预热、记录和抛出会话故障，不发送失败或恢复通知。development 环境中，最终业务 Run 失败时由外层业务 Flow 按工作负载、业务标识和 Flow Run 去重后发送一次企业微信告警。

- 认证告警仅在探活或下载响应能够明确判定为认证失效时发送。非登录 `302` 不发送“自动登录告警”，也不消费登录刷新预算。
- 基础设施告警明确说明不会自动重登，避免把网络、DNS、TLS、代理、限流或上游问题误导为账号问题。
- 告警不包含 Cookie、Token、账号、密码、Webhook、完整内部 URL、重定向位置或响应正文。

## 业务数据尚未生成

`EmptyReportDataError` 表示下载接口已正常响应，但业务侧返回 `returncode=1`，并说明对应地区暂未生成报表数据。这不是 Cookie、登录、HTTP 或网络故障，因此不得清理 Cookie、启动浏览器登录或消费会话刷新预算。

只有报表配置显式设置 `wait_for_change.enabled=true` 时，Flow 才会按 `poll_interval_seconds` 轮询至 `max_wait_minutes`；否则立即以“业务空数据”失败，保留报表名称、返回码和业务说明，不在异常或告警中输出下载 URL。当前 `爱家亲情网市公司通报` 与 `爱家V网` 都设置为 `false`，因此会立即失败，等待策略需由业务配置明确开启。

## 下载后处理失败

下载 Task 完成不代表整条通报 Flow 已完成。以下问题发生在下载之后，不应误判为 HTTP 请求或会话问题，也不应触发重新登录：

| 现象 | 常见错误 | 处理方式 |
| --- | --- | --- |
| Flow 拒绝运行根相对路径 | `不允许绝对路径、父目录路径或 runtime/ 前缀` | 检查是否经 `resolve_runtime_relative_path()` 解析，Flow 生成的路径必须位于共享 Runtime 根目录 |
| 仍读取仓库内旧 `runtime/` | `FileNotFoundError`，路径位于仓库 `runtime/flow/...` | 排查遗留配置或路径拼接，统一使用根相对路径，例如 `flow/<任务>/output/...` |
| Excel 截图或分页初始化失败 | 无法设置稳定打印机、`ActivePrinter` COM 错误 | 检查 `Microsoft Print to PDF`、专用 Windows 会话和虚拟打印机干扰；不要重登或重试下载 |
| 比对、模板更新、消息组装或发送失败 | 对应 Task/Flow 异常 | 按失败 Task 排查输入文件、模板结构、Excel 或企业微信配置；下载成功产物可作为诊断依据 |

判定顺序：先查看 `download_reports_task` 是否为 `Completed`，再查看失败栈中的首个项目内 Task。只有下载 Task 本身报告认证、网络、HTTP 或响应格式错误时，才按“下载与外部服务”处理。

## 排查顺序

1. 先看阶段、原因和 HTTP 状态，判断是否属于认证失效。
2. 认证失效时等待当前单次刷新结果；不要手工并发启动第二个登录进程。
3. 基础设施问题优先检查网络和上游状态，不要反复清理 Cookie 或重登。
4. `json_value_mismatch`、非登录 3xx、空响应在刷新后仍存在时，核对接口契约和配置字段。
5. 需要进一步诊断时查看受控本地日志和配置字段名，不输出认证材料或完整内部 URL。
