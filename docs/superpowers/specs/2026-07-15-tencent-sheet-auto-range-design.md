# 腾讯文档自动读取范围优化设计

## 目标

腾讯文档 Sheet 的元数据同时包含已用单元格边界和预分配容量。下载服务的
自动范围不应把预分配的空白行列写入导出的 Excel。

用户显式填写读取范围时，服务必须严格按该范围请求，不能按元数据截断。

## 现状

`services/tencent_sheet_service.py` 的 `resolve_sheet_range()` 目前优先使用
`rowTotal` 与 `columnTotal`。这两个字段表示工作表容量；例如一个实际只有
2 行、1 列数据的 Sheet 可能仍报告 200 行、26 列容量，因而 `auto` 会读取
`A1:Z200`。

同一份元数据中的 `rowCount` 和 `columnCount` 表示当前已用边界。当前链接的
目标 Sheet 返回 `rowCount=2`、`columnCount=1`。

## 设计

### 自动范围

对于空范围、`auto`、`used` 与 `used_range`：

1. 优先使用 `rowCount` 与 `columnCount`。
2. 仅在其中一个实际边界字段缺失或无效时，回退使用 `rowTotal` 与
   `columnTotal`。
3. 若两组字段都无法形成正整数边界，维持现有错误提示，要求用户填写范围。

因此，示例 Sheet 的自动范围从 `A1:Z200` 变为 `A1:A2`。

### 显式范围

用户提供的 A1 范围（例如 `A1:F100`）视为明确意图：

- 不使用 Sheet 元数据缩小范围。
- 仍沿用现有按请求上限分块的逻辑。
- 若腾讯接口在后续分块返回范围无效，保留现有的“已读取数据后停止”处理，
  以兼容服务端实际边界小于请求范围的情况。

### 影响范围

仅调整范围边界解析及其单元测试：

- `services/tencent_sheet_service.py`
- `tests/test_tencent_sheet_service.py`

不增加新的配置字段，不改变显式范围的接口格式，也不改变腾讯文档鉴权或
导出文件路径。

## 验证

测试必须覆盖：

1. 自动范围优先使用 `rowCount` 与 `columnCount`。
2. 实际边界字段无效或缺失时回退至容量字段。
3. 显式范围不因元数据容量而被截断。
4. 现有下载、分块和范围无效处理测试继续通过。
