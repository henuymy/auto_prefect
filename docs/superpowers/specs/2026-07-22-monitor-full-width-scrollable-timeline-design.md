# 运行监控中心全宽与可滚动时间线设计

## 目标

让运行监控中心在桌面端使用整个视口的可用宽度，而不是在超过 1600px 时保留大片左右空白。时间线记录很多时，用户可以在左侧面板内连续向下滚动查看，不需要不断点击“加载更多”。

## 范围

- 移除 `monitor-header`、筛选工具栏、主网格和加载失败状态的 1600px 最大宽度；页面仍保留 24px 内边距，避免内容紧贴浏览器边缘。
- 时间线保留现有“按日期分组”和逐日展开/收起交互；“下拉”在此处指列表的纵向滚动，不新增日期下拉选择器。
- 桌面端时间线面板的标题固定在面板顶部，记录分组区域在可用高度内独立滚动，并使用细滚动条和滚动边界隔离。
- 时间线直接呈现当前筛选结果的全部记录；移除仅渲染 10 条和“加载更多时间线”的批量入口。
- 小屏幕继续采用单列自然页面滚动，不强制固定高度，避免嵌套滚动影响触屏浏览。

## 组件与数据流

`MonitorCenter` 已将 `filteredRuns` 按最新运行时间排序。时间线分组将直接基于该数组构建，不再经过 `visibleTimelineCount` 截断。`timelineDayExpanded` 继续以日期为键维护展开状态，今天默认展开，历史日期默认收起。

时间线分组容器将拥有明确的无障碍名称和键盘焦点，说明它可上下滚动查看全部记录。点击任一时间线记录仍复用现有详情抽屉逻辑；筛选条件变化、实时更新和详情打开逻辑不改变。

## 布局与响应式

桌面端主网格保持左时间线、运行记录、详情面板的既有列结构。取消最大宽度后，中央运行记录列吸收额外的横向空间；详情面板打开时仍使用现有三列规则。

在宽度至少 761px 时，时间线面板使用视口可用高度并限制最大高度，标题保持可见，`.timeline-groups` 作为唯一纵向滚动区域。小于该断点时，时间线恢复内容高度，随页面正常滚动。

## 测试与验收

- 使用超过 10 条的同日运行记录验证时间线仍能渲染全部项目，且不再显示“加载更多时间线”。
- 验证时间线列表有可访问名称，供键盘用户识别可滚动区域。
- 通过 CSS 契约测试验证桌面时间线使用纵向滚动、主内容不再含 1600px 最大宽度，并确认手机断点仍关闭固定高度。
- 运行监控中心测试、类型检查和生产构建；在桌面视口手动检查左右空白消失、时间线独立滚动和详情抽屉布局。

## 非目标

- 不修改监控 API、WebSocket、Prefect 数据或记录筛选语义。
- 不新增虚拟列表、无限滚动或日期选择器。
- 不改变运行记录表格的分页和移动端横向滚动行为。
