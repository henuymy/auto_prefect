# 比对服务根相对路径与兼容层审计

## 目标

使比对服务将受控的运行根相对路径解析到共享运行根，避免 Flow 生成的
`flow/<任务>/...` 下载产物被错误解析到代码仓库。同时建立旧 `runtime/...`
兼容入口的下线审计清单。

## 路径规则

- 受控运行根相对路径由 `resolve_runtime_relative_path()` 解析，例如
  `flow/<任务>/tmp/downloads/...`、`session/...`、
  `modules/<模块>/output/...`。
- 普通项目路径仍按调用方的 `base_dir` 解析，例如 `templates/...` 和
  `config/...`。
- 绝对路径保留现有解析语义。
- 旧 `runtime/...` 前缀不再作为比对服务的有效业务输入；服务应明确拒绝它，
  不得将其降级为项目相对路径。

## 审计清单

清单逐项记录：旧解析函数、生产调用者、脚本参数、配置样例和测试夹具。每项
只能标记为“已迁移”“待迁移”或“保留为拒绝旧格式”。只有所有项目均为已迁移
或明确保留时，才能计划删除旧兼容解析。

## 验收

- `compare_service.resolve_path()` 将 `flow/...` 解析到 `AUTO_NOTIFY_RUNTIME_ROOT`。
- `templates/...` 等项目路径仍解析到给定 `base_dir`。
- `runtime/...` 在比对服务中抛出明确的 `ValueError`。
- 审计清单位于仓库文档，且包含本轮发现的比对服务入口和两项运维脚本入口。
- 相关 pytest 测试通过；不执行登录、下载、浏览器、Prefect 或通知操作。
