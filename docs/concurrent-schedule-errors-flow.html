常见错误位置

同一个并发批次里，不同错误出现的位置不同，处理方式也不同。

并发重登互相覆盖

最核心的问题。表现为多个流程都登录，后登录的刷新 Cookie，先登录的下载变成 reCode=1101。解决：登录锁 + 锁内总是复检。

旧 Edge 干扰

真正重登前关闭自动登录 profile 对应的 Edge。复检成功复用 Cookie 时不能关闭，否则会打断刚登录好的流程。

下载中 session 过期

说明下载接口明确拒绝当前 Cookie。处理：强制进入登录锁，锁内复检，必要时重登，然后当前下载只重试一次。

网络超时

ConnectTimeout、ReadTimeout、ConnectionError 属于网络问题，走网络重试，不应该触发重新登录。

登录页异常

多终端工具弹窗、安全检查失败、系统异常页会导致登录本身失败。应保存 runtime/login_debug 下的 HTML 和截图。

Worker 离线

如果走 Prefect 调度，Work Pool 红点或 Last Polled 很久不更新，说明调度没有 worker 执行，不是 Cookie 问题。

一次异常批次的时间线

下面展示修复前后差异。修复后的关键是“等待锁以后不直接重登，而是先复检”。

修复前 16:00:00
Task A、B、C 同时启动，都发现 Cookie 探活失败。
修复前 16:00:05
A 登录成功写入新 Cookie，B 拿到锁后仍强制重登，C 后续也可能再重登。
修复前 16:00:19
部分流程下载时拿到已被覆盖的 Cookie，出现 session 已过期 或 reCode=1101。
修复后 16:00:00
Task A、B、C 同时启动，A 进入登录锁真正登录，B、C 等待。
修复后 16:00:20
B、C 拿到锁后先复检，发现 A 已刷新 Cookie，于是 reused_after_lock，不再重复登录。
修复后 16:00:25
多个 task 使用同一份最新 Cookie 并行下载；若某个下载仍明确过期，再进入同一套锁内复检逻辑。
