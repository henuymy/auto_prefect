自动通报完整流程图

覆盖 Prefect 调度、Stage 级 Session 探活、下载重试、比对、模板更新、企业微信发送与模板提交。

流程控制 成功路径 判断 / 等待 / 重试 失败终止 外部系统 / 文件

1. 调度与配置

Prefect Cron 触发 Deployment

多个 deployment 可以共用 auto_notify_flow，通过不同 config_path 区分任务。

读取任务配置

  • config/tasks/*.json
  • 读取 report_config_path
  • 生成本次 runtime_dir

校验报表 Schema

必须使用 downloads[]、compare_sources[] 新结构。

提取本次需要的 Stage

只从启用的 downloads[].stage 去重，例如只需要 city_ops 就不检查其他 stage。

2. 登录态准备与探活

构建 Login Config

读取 autologin.json，用本次实际 stage 覆盖 required_stages。

静态检查 Cookie Dump

  • 文件是否存在
  • stage 是否齐全
  • Cookie 是否过期或快过期
  • cookie_dump 是否超过最大年龄

Stage Probe 真实探活

静态检查通过后，按 stage 请求轻量接口验证服务端是否还认当前 session。

探活成功

返回 reused 或 reused_after_wait，进入下载。

探活失败 / Cookie 不可用

进入 runtime/locks/login.lock 登录锁，同一时间只允许一个流程执行自动登录。

自动登录并重新 Dump Cookie

执行 login_command，Selenium 登录 NGBOSS/USM 并刷新 runtime/cookies/cookie_dump.json。

登录后再次校验 + 探活

仍失败则终止；成功则返回 refreshed。

3. 下载与重试

构建下载配置

把报表 downloads[] 合并为 download_reports_task 的 reports[]。

按 Stage 取 Cookie / Storage

  • Cookie header
  • headers_from_cookies
  • headers_from_session_storage
  • headers_from_local_storage

请求下载接口

支持文件下载、JSON 转 Excel、JSON 下钻转 Excel。

发现 Session 过期

识别 401/403、login.jsp、reCode=1101、登录超时等。

强制重新登录后重试一次

调用 prepare_session(force_refresh=True)，成功后重新执行下载。

下载 Manifest

写出下载结果、输出文件路径、行数、耗时等信息。

4. 后处理与发送

构建比对配置

根据 compare_sources[] 和下载 manifest 找到新报表路径。

执行报表比对

使用 openpyxl 或 com，判断 same/changed/invalid。

等待变化策略

如果启用 wait_for_change 且结果仍是 same，会按间隔重新下载和比对，直到变化或超时。

更新模板

按变更结果写入模板，必要时通过 Excel COM 刷新公式。Excel COM 使用全局锁排队。

生成企业微信消息包

截图、文本读取、预览图和 package 文件。

发送并提交模板

发送企业微信；成功后按配置提交正式模板并备份。

Stage 探活接口

Stage 接口 成功条件 动态认证来源
report_analysis POST /bicpreport/client/getLoginName returnCode == "0" Cookie ssr-token → Header Ssr-Token
city_ops POST /dszzCombat/.../base/getUserInfo reCode == "0000" sessionStorage uapToken → Header uapToken
smart_ops GET /zhyypt/smop/base/refresh HTTP 200，允许空响应体 sessionStorage zhyyptInfo.accessToken → Header user-info

失败与兜底规则

探活不是保活。它只判断当前 dump_cookie 是否仍被服务端认可；失败后必须重新登录并重新 dump。
信号 处理
401 / 403 判定 session 失效，强制重新登录。
URL 包含 login.jsp、logout.action、kickedOut 判定被踢或回登录页，强制重新登录。
JSON reCode=1101 判定单点登录超时，强制重新登录。
下载阶段仍失败 保留现有兜底：重新登录后再下载一次；第二次仍失败则终止。
