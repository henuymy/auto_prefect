# Report Downloader

## Workflow

Use this skill after `autologin` has produced `autologin/runtime/cookie_dump.json`.

1. Confirm the needed application stage exists in the cookie dump, such as `report_analysis`, `smart_ops`, or another configured stage.
2. Add report download tasks to `report-downloader/config.json`.
3. Run the downloader; files are saved under `report-downloader/runtime/downloads` by default.

## Commands

Run from the workspace root:

```powershell
python report-downloader\scripts\download_reports.py --config report-downloader\config.json
```

Preview configured tasks without network requests:

```powershell
python report-downloader\scripts\download_reports.py --config report-downloader\config.json --dry-run
```

## Configuration

- `cookie_dump_path`: path to the Cookie JSON generated by `autologin`.
- `output_dir`: folder where downloaded reports should be written.
- `verify_ssl`: set `false` for internal HTTPS systems with non-standard certificates.
- `trust_env`: keep `false` when local proxy environment variables should not affect requests.
- `proxies`: set explicit HTTP/HTTPS proxies when Postman succeeds through a configured proxy. Leave `{}` for direct requests.
- `reports`: list of report tasks.
- Each report task must include `name`, `stage`, and `url`.
- `stage` must match a stage in `cookie_dump.json`; the task uses cookies captured from that stage.
- Add `method`, `params`, `data`, `json`, and `headers` only when needed.
- Use `method: "POST"` plus `data` for `application/x-www-form-urlencoded` exports.
- Use `headers_from_cookies` when a request header must mirror a captured cookie, such as `{"ssr-token": "ssr-token"}`.
- Use `csrf_headers_from_cookies` when one cookie stores the CSRF header name and another stores the value, such as `{"ssr-header": "ssr-token"}`.
- Use `allow_redirects` when the export endpoint returns a 302 to the actual file response.
- Do not configure `Cookie` manually; cookies are loaded from the selected stage and sent by the HTTP session.
- Omit `cookie_names` for browser-like requests that should carry all cookies from the selected stage; use it only when a report explicitly requires a smaller cookie set.
- Do not rename downloads by default; filenames come from the response `Content-Disposition` header when the system provides one.

Keep URLs and request parameters in config, not in the script. The script is a generic downloader.

## Outputs

- Downloaded report files are saved to `runtime/downloads`.
- A run manifest is saved to `runtime/download_manifest.json`.
- Runtime outputs may contain sensitive business data and should not be committed.
